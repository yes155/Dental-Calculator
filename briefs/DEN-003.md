## 5. Direct-answer target

Opening may say that Forbes Advisor reports an ADA-attributed **$20,000–$45,000** figure for a “mouthful of implants,” but the source does **not** specify whether that amount represents one or two arches, a fixed or removable restoration, the number of implants, or which surgical/prosthetic components are included. Therefore it is a broad context figure, not a per-arch calculator default.

Do not call this range “typical per arch.” Do not double or halve it.

User-facing H1: `Full-mouth dental implants cost`. Keep the more technical per-arch normalization framing in supporting copy, metadata and calculator explanation rather than the H1.

## 7. Calculator role — CALC-003
Purpose: Normalize a written full-arch/full-mouth quote by arch count and quote scope.  
No national price default.  
Required inputs: quoted total; number of arches covered by that quote (1 or 2); restoration label from the quote if known; inclusion statuses for implant placement, temporary/final prosthesis and other package items; insurance mode and same-scope insurer estimate if known.  
Outputs: entered quote total, normalized per-arch amount, scope-completeness warnings, conditional patient-responsibility estimate.  
Prohibited: deriving implant count, deciding fixed vs removable suitability, using All-on-4 prices as generic full-arch defaults.

### Guided UX contract inherited from approved CALC-001
- Keep the frozen arithmetic and evidence rules unchanged.
- Use three stages: `Your quote` → `What's included` → `Insurance & result`.
- Step 1 requires the user to enter the written total, choose one or two arches, and explicitly confirm that the arch count is stated by the quote.
- Restoration wording uses plain-language fixed/removable/not-stated choices and remains descriptive only.
- Main package items remain visible; secondary items use progressive disclosure.
- Package items default to `Not sure` rather than being silently treated as included or absent.
- Separate-charge amount fields appear only when relevant.
- Internal calculator IDs are metadata only and must not render visibly.
- Published $20,000–$45,000 context remains separate from calculator arithmetic.
- Prefixed money fields must focus/error-highlight as one `$ + amount` control.
- Result shows the three main package items first; secondary package details are collapsed.
- If an insurance amount is entered while package details remain incomplete, the UI explains that the after-insurance amount needs clearer quote details instead of showing an unexplained `Not shown` value.
